# Data Model: Reserve Stock When an Order Is Placed (US-01)

Phase 1 output for [plan.md](plan.md). The domain model and the persistence model are separate
(constitution Principle I) and mapped explicitly in `infrastructure.persistence`.

## 1. Domain model (`com.ecommerce.inventory.domain`, plain Java)

### Value objects (immutable records, validated in the compact constructor)

| Type | Fields | Invariants |
|---|---|---|
| `ProductId` | `String value` | not null, not blank, at most 64 characters; compared exactly (case-sensitive) |
| `OrderId` | `UUID value` | not null |
| `ReservationId` | `UUID value` | not null; `ReservationId.newId()` generates a random UUID |
| `Quantity` | `long value` | `> 0`; `plus(Quantity)` adds the `long` values. Inbound quantities are `int`, so a consolidated sum cannot overflow and an over-large sum is simply insufficient stock (spec edge case "very large quantity") |
| `RequestedItem` | `ProductId productId`, `Quantity quantity` | |
| `RequestedItems` | `List<RequestedItem> items` (sorted by `productId`) | built with `RequestedItems.consolidate(List<RequestedItem>)`: sums quantities per product (FR-004); not empty; one entry per product |
| `ItemFailure` | `ProductId productId`, `long requested`, `int available`, `FailureKind kind` | `requested > 0`, `available >= 0`; `available == 0` when `kind == UNKNOWN_PRODUCT` |

### Enums

| Enum | Values | Notes |
|---|---|---|
| `ReservationStatus` | `RESERVED`, `REJECTED` | `RELEASED` is added by US-02 |
| `FailureKind` | `UNKNOWN_PRODUCT`, `INSUFFICIENT_STOCK` | |
| `RejectionReason` | `INSUFFICIENT_STOCK("insufficient stock")`, `UNKNOWN_PRODUCT("unknown product")`, `UNKNOWN_PRODUCT_AND_INSUFFICIENT_STOCK("unknown product and insufficient stock")` | `RejectionReason.from(Set<FailureKind>)` (FR-008); `wireValue()` is the text published |

### Aggregate `StockItem`

| Field | Type | Notes |
|---|---|---|
| `productId` | `ProductId` | identity |
| `availableQuantity` | `int` | `>= 0` at all times (FR-009) |

Behaviour:

- `canSupply(Quantity q)`: `availableQuantity >= q.value()`.
- `reserve(Quantity q)`: decreases `availableQuantity`; throws `InsufficientStockException` if it
  would go below zero. It is only called after the all-or-nothing decision, so in normal operation
  it never throws; the check is the domain half of the "never negative" guarantee.

### Aggregate `Reservation`

| Field | Type | Notes |
|---|---|---|
| `id` | `ReservationId` | generated by Inventory; `aggregateId` of outbound events |
| `orderId` | `OrderId` | unique across reservations (FR-013) |
| `status` | `ReservationStatus` | |
| `items` | `RequestedItems` | consolidated requested items |
| `rejection` | `Optional<Rejection>` | present only when `REJECTED`: `RejectionReason reason`, `List<ItemFailure> failures` (sorted by `productId`) |
| `createdAt`, `updatedAt` | `Instant` | |
| `domainEvents` | `List<InventoryDomainEvent>` | pulled once by the application service |

Factory (the only way to create a reservation; all business rules live here):

```text
Reservation.decide(ReservationId id, OrderId orderId, RequestedItems items,
                   Map<ProductId, StockItem> lockedStock, Instant now) -> Reservation
```

1. For each requested item (already consolidated and sorted): unknown if absent from
   `lockedStock` → `ItemFailure(UNKNOWN_PRODUCT, requested, 0)`; insufficient if
   `!canSupply` → `ItemFailure(INSUFFICIENT_STOCK, requested, available)`.
2. No failures → call `reserve` on every `StockItem`, status `RESERVED`, raise `StockReserved`.
3. Any failure → no `StockItem` is touched, status `REJECTED`,
   `reason = RejectionReason.from(kinds)`, raise `StockRejected` (FR-005 to FR-008).

`Reservation.restore(...)` rebuilds a persisted reservation without raising events (used by the
repository mapper).

### State transitions

```text
            decide(): all items available            decide(): any unknown/insufficient
(none) ───────────────────────────────▶ RESERVED    (none) ──────────────────────────▶ REJECTED
```

Both states are final in US-01. US-02 adds `RESERVED → RELEASED`.

### Domain events (`domain.event`, sealed interface `InventoryDomainEvent`)

| Event | Fields |
|---|---|
| `StockReserved` | `ReservationId reservationId`, `OrderId orderId`, `List<RequestedItem> items`, `Instant reservedAt` |
| `StockRejected` | `ReservationId reservationId`, `OrderId orderId`, `RejectionReason reason`, `List<ItemFailure> failures`, `Instant rejectedAt` |

### Domain exceptions (`domain.exception`, base `InventoryDomainException extends RuntimeException`)

`InvalidQuantityException`, `InvalidProductIdException`, `InsufficientStockException`. A
business rejection is **not** an exception: it is a `REJECTED` reservation.

### Repository ports (`domain.repository`)

| Port | Methods |
|---|---|
| `StockItemRepository` | `Map<ProductId, StockItem> lockAllOrderedByProductId(Set<ProductId> ids)`; `void saveAll(Collection<StockItem> items)` |
| `ReservationRepository` | `Optional<Reservation> findByOrderId(OrderId id)`; `void save(Reservation r)` |

The domain knows nothing about messages. The serialized outcome message is stored through the
application port `OutcomeMessageRepository` (section 2) in the same transaction.

## 2. Application layer (`com.ecommerce.inventory.application`)

| Type | Kind | Purpose |
|---|---|---|
| `ReserveStockCommand` | record | `UUID eventId`, `OrderId orderId`, `List<RequestedItem> items` (not yet consolidated) |
| `ReserveStockOutcome` | sealed interface | `Decided(ReservationId, ReservationStatus)`, `Redelivered(ReservationId)`, `DuplicateOrderIgnored(ReservationId existing)` |
| `ReserveStockService` | service | orchestrates R3/R4: idempotency check → duplicate-order check → lock → `Reservation.decide` → save all in one transaction → publish after commit → outbound dead-letter on failure |
| `OutboundMessage` | record (`port`) | `UUID eventId`, `String topic`, `String key`, `String payload` (JSON) |
| `OutboundMessageFactory` | port | maps `InventoryDomainEvent` → `OutboundMessage` (implemented in `infrastructure.kafka`) |
| `OutboundMessagePublisher` | port | `void publish(OutboundMessage)`; throws `PublishFailedException` |
| `OutcomeMessageRepository` | port | `void save(ReservationId, OutboundMessage)`; `Optional<OutboundMessage> findByReservationId(ReservationId)` (republish on redelivery, FR-016) |
| `OutboundDeadLetterRepository` | port | `void recordFailure(OutboundMessage, String error, Instant nextRetryAt)` |
| `ProcessedEventRepository` | port | `Optional<ProcessedEvent> find(UUID eventId)`; `void save(ProcessedEvent)` |
| `ProcessedEvent` | record | `UUID eventId`, `String topic`, `ProcessedOutcome outcome`, `ReservationId reservationId`, `Instant processedAt` |
| `ProcessedOutcome` | enum | `RESERVATION_DECIDED`, `DUPLICATE_ORDER_IGNORED` |

## 3. Persistence model (PostgreSQL, Flyway `V2__reserve_stock_schema.sql`)

JPA entities live in `infrastructure.persistence` and never leave it.

### `stock_items`

| Column | Type | Constraints |
|---|---|---|
| `product_id` | `varchar(64)` | PK |
| `available_quantity` | `integer` | `NOT NULL`, `CHECK (available_quantity >= 0)` (FR-009) |
| `updated_at` | `timestamptz` | `NOT NULL DEFAULT now()` |

### `reservations`

| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | PK |
| `order_id` | `uuid` | `NOT NULL`, `UNIQUE` (FR-013) |
| `status` | `varchar(16)` | `NOT NULL`, `CHECK (status IN ('RESERVED','REJECTED'))` |
| `rejection_reason` | `varchar(64)` | nullable; `CHECK ((status = 'REJECTED') = (rejection_reason IS NOT NULL))` |
| `created_at`, `updated_at` | `timestamptz` | `NOT NULL` |

### `outcome_messages`

The exact outcome message of each reservation, saved in the reservation's transaction and
republished verbatim on redelivery (FR-016, FR-017).

| Column | Type | Constraints |
|---|---|---|
| `event_id` | `uuid` | PK |
| `reservation_id` | `uuid` | `NOT NULL`, `UNIQUE`, FK → `reservations(id)` |
| `topic` | `varchar(255)` | `NOT NULL` |
| `message_key` | `varchar(255)` | `NOT NULL` |
| `payload` | `jsonb` | `NOT NULL` |
| `created_at` | `timestamptz` | `NOT NULL` |

### `reservation_items`

| Column | Type | Constraints |
|---|---|---|
| `reservation_id` | `uuid` | FK → `reservations(id)` `ON DELETE CASCADE` |
| `product_id` | `varchar(64)` | no FK (unknown products are recorded too) |
| `requested_quantity` | `bigint` | `NOT NULL`, `CHECK (requested_quantity > 0)` (consolidated sums can exceed 32 bits) |
| `failure_kind` | `varchar(32)` | nullable; `CHECK (failure_kind IN ('UNKNOWN_PRODUCT','INSUFFICIENT_STOCK'))` |
| `available_at_decision` | `integer` | nullable; `CHECK (available_at_decision >= 0)`; set only for failing items |
| | | PK `(reservation_id, product_id)` |

### `processed_events`

| Column | Type | Constraints |
|---|---|---|
| `event_id` | `uuid` | PK |
| `topic` | `varchar(255)` | `NOT NULL` |
| `outcome` | `varchar(32)` | `NOT NULL`, `CHECK (outcome IN ('RESERVATION_DECIDED','DUPLICATE_ORDER_IGNORED'))` |
| `reservation_id` | `uuid` | `NOT NULL`, FK → `reservations(id)` |
| `processed_at` | `timestamptz` | `NOT NULL` |

### `outbound_dead_letters`

| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | PK |
| `event_id` | `uuid` | `NOT NULL`, `UNIQUE` (same event is never stored twice; a repeat failure updates `last_error`) |
| `topic` | `varchar(255)` | `NOT NULL` |
| `message_key` | `varchar(255)` | `NOT NULL` |
| `payload` | `jsonb` | `NOT NULL` |
| `status` | `varchar(16)` | `NOT NULL`, `CHECK (status IN ('PENDING','RESOLVED','EXHAUSTED'))` |
| `retry_count` | `integer` | `NOT NULL DEFAULT 0`, `CHECK (retry_count >= 0)` |
| `next_retry_at` | `timestamptz` | `NOT NULL` |
| `last_error` | `text` | `NOT NULL` |
| `created_at`, `updated_at` | `timestamptz` | `NOT NULL` |
| | | index `(status, next_retry_at)` for the US-03 worker |

### `consumed_dead_letters`

| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | PK |
| `topic` | `varchar(255)` | `NOT NULL` |
| `partition` | `integer` | `NOT NULL` |
| `record_offset` | `bigint` | `NOT NULL` |
| `message_key` | `text` | nullable |
| `payload` | `text` | nullable (raw value, stored as received even if not JSON) |
| `error` | `text` | `NOT NULL` (exception class and message) |
| `attempts` | `integer` | `NOT NULL`, `CHECK (attempts >= 1)` |
| `failed_at` | `timestamptz` | `NOT NULL` |
| | | `UNIQUE (topic, partition, record_offset)` (recovery is idempotent) |

## 4. Mapping summary

| Domain | Persistence |
|---|---|
| `StockItem` | `stock_items` row (`StockItemEntity`) |
| `Reservation` + `RequestedItems` + `Rejection` | `reservations` row + `reservation_items` rows (failing items carry `failure_kind` and `available_at_decision`) |
| `OutboundMessage` of the decision | `outcome_messages` row |
| `ProcessedEvent` | `processed_events` row |
| `OutboundMessage` that failed to publish | `outbound_dead_letters` row |
| Consumer record that failed | `consumed_dead_letters` row |
